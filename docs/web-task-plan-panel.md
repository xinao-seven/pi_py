# 前端：计划与任务合并成右上角悬浮面板

适用范围：`web/`（`ChatWindow.vue` / `TaskPlanPanel.vue` / `TaskStepList.vue`）
背景：M2 的任务面板与 M4 的计划面板原来都钉在输入框上方（`composer-dock` 里的同一条 strip）。

---

## 1. 为什么要改

两个面板合起来最多占掉半屏，而它们的**内容高度重叠**：

- M4 起「计划」就是 `origin='plan'` 的任务，`PlanView` 只是这条任务的投影；
- 因此模型提交计划后，`TaskPanel` 里也会出现**同一条任务**（同一份步骤列表被渲染两遍）；
- 两套操作按钮并存（计划的「跳过/改名」与任务的「开始/完成/阻塞」）让人分不清该点哪个。

结论：两个面板合并成一个，并且**从对话框上方挪走**，改成右上角按钮点开的悬浮面板。

---

## 2. 合并规则（只有一条）

> **计划活跃时，面板以计划视角展示它自己的那条任务；任务区只在会话里还存在「不是这条计划」的任务时才出现。**

判定用 `plan.planId` 是否为空串（空串 = 这个会话当前没有计划）与 `task.id === plan.taskId`：

| 会话状态 | 面板内容 |
| --- | --- |
| 计划活跃，且 `task.id === plan.taskId` | 只渲染计划区（含步骤列表），**不再重复渲染任务区** |
| 计划活跃，另有一条用户任务 | 计划区（title/goal/步骤/计划操作）+ 「会话任务」区（带任务标题与状态徽标、自己的步骤列表） |
| 没有计划，只有任务 | 只有任务区（面板头部徽标即任务状态），列表与操作与旧 `TaskPanel` 一致 |
| 都没有 | 空态提示 + 头部「新建任务」入口 |

**实现落点**：`web/src/components/TaskPlanPanel.vue`。判断逻辑集中在 `planActive` / `taskSection`
两个 `computed` 里，模板只按它们分支，因此「同一条任务渲染两遍」在结构上不可能发生。

## 3. 交互契约

| 项 | 行为 |
| --- | --- |
| 入口按钮 | `chat-header` 的 `header-meta` 里，文案「计划/任务」，带完成计数（如 `2/5`） |
| 注意力提示 | 需要用户动手时按钮点亮（accent 边框）：`plan.awaitingUserAction`、任务 `blocked`、有 `task_recovery_required` |
| 面板位置 | 头部正下方、右对齐（`position: absolute; top: calc(100% + 4px); right: 14px`）；**不可拖动**，没有拖拽逻辑 |
| 尺寸 | `width: min(400px, calc(100vw - 28px))`，`max-height: min(64vh, 560px)`，内容区自己滚动 |
| 关闭方式 | 再点按钮 / 面板右上角 ✕ / `Esc` / 点面板与按钮之外的任何地方 |
| 自动展开 | **只有一种情况**：计划进入 `proposed`（等待「确认并执行」）。否则默认收起，避免悬浮面板天天糊在消息上 |
| 切换会话 | 收起面板并复位自动展开标记（面板属于单个会话） |

「待确认的计划必须被看见」这条原来的保证由**自动展开 + 按钮点亮**共同兑现：
即便用户手动收起，按钮上的 accent 边框与徽标计数也仍然醒目。

### 3.1 层级与响应式

- 面板 host `z-index: 50`：高于分支条（`12`），低于审批/提问/设置弹窗（`60` / `100`）——弹窗永远在上层。
- 锚点是 `.chat-header`（加了 `position: relative`），面板是它的绝对定位子元素，
  **不参与** `chat-window` 的 flex 布局，所以不会再把消息区顶上去。
- 窄屏（`max-width: 760px`）下：`right: 8px`、宽度 `calc(100vw - 16px)`、`max-height: 70vh`。

## 4. 组件结构

```
ChatWindow.vue          workPanelOpen / workPanelHost（定位壳）/ workPanelButton（入口按钮）
                        + 自动展开的 watch + Esc/点外关闭的 document 监听
  └─ TaskPlanPanel.vue  面板内容体：头部（徽标/标题/计数/工具）、恢复块、计划区、任务区、空态
       └─ TaskStepList.vue  步骤列表：计划视角与任务视角共用同一套行渲染
```

- **`TaskPlanPanel.vue`**：只发事件（`close` / `refresh` / `plan*` / `stepPatch` / `stepRemove` /
  `create` / `addStep` / `setStepStatus` / `removeStep` / `cancelTask` / `resumeTask`），
  所有写入仍由 `ChatWindow` 的 `actTask` / `actPlan` 包装（乐观并发、`409` 刷新后重试一次）。
- **`TaskStepList.vue`**：`mode: 'plan' | 'task'` 决定操作按钮走哪条通道
  （计划：改名/跳过/恢复/删除；任务：开始/完成/阻塞/解除/重开/删除）。
  步骤副标题（证据 / 验证声明 / 阻塞原因 / 下一步）**只保留一份实现**——两套视角的原始规则完全一致，
  分开写只会让措辞漂移。阻塞原因表单与「删除已完成步骤需确认」也随行内联在这个组件里。
- 计划的步骤编辑按钮平时透明度为 0，hover / 键盘聚焦才出现，避免面板里密密麻麻全是按钮。

## 5. 与旧组件的差异（有意为之）

| 变化 | 说明 |
| --- | --- |
| 计划步骤不再提供手工「完成」 | 服务端要求完成必须带证据并按 `verification` 校验（`complete_step` 由模型调用），手工点「完成」本来就会被拒；计划终态外仍可改名/跳过/恢复/删除 |
| 「折叠成一行摘要」的交互去掉 | 折叠现在由关闭悬浮面板承担，不需要面板内部再嵌一层折叠 |
| 执行中/已暂停的「按我的要求调整」现在真的能点 | 旧 `PlanProgress` 在这一分支里渲染了按钮却没有输入框，`refineText` 永远为空 → 按钮恒为 disabled；合并后补上了输入框（`提交要求`） |
| 另有会话任务时会在面板里显示任务标题 | 旧版两个面板各自为政时不会同时出现，合并后必须能分辨是哪条任务 |

其余能力（新建任务、加步骤、阻塞原因必填、终态隐藏编辑、`busy` 禁用、M3 中断恢复块的
「继续执行 / 重试当前步骤 / 待验证产物 / 需要确认副作用风险」）全部保留。

## 7. 已知限制

- 面板**不可拖动**、不可调整大小（用户明确要求：悬浮即可，别做成第二套窗口系统）。
- 不做「固定展开」偏好持久化：刷新后回到收起态（待确认的计划仍会自动展开）。
- 面板只对应**当前会话**；跨会话的任务列表仍需走 `GET /api/tasks`，UI 未提供。
- 点面板外关闭依赖 `document` 上的 `pointerdown` 监听：如果将来出现「点某个浮层不该关面板」的场景，
  需要在 `onDocumentPointerDown` 的忽略列表里加上那个元素。
